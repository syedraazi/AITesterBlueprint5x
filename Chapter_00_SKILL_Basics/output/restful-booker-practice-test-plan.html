1. Objective

The objective is to assess the quality, functionality, and reliability of the Restful Booker API at https://restful-booker.herokuapp.com, focusing on booking create, read, update, and delete (CRUD) flows, input validation, authentication, and API responses.

Testing will also consider response behavior, error handling, data consistency, and the API documentation. Experiment impact metrics and guardrail metrics are not defined in the supplied information and must be agreed before any experiment-related testing.

2. Scope

In scope

  • Functional and CRUD testing of documented booking operations.
  • Input and response data validation, including invalid, missing, and boundary values.
  • Authentication and authorization checks for protected operations.
  • Error handling, integration/data consistency, regression, and exploratory testing.
  • Performance and load behavior, concurrency, rate limiting, and security checks at a test-plan level.
  • API documentation review and CI/CD behavior where the relevant pipeline is available.

Out of scope / not specified

  • Unspecified third-party services, product features, service-level objectives, and compliance requirements.
  • Production data changes or destructive testing outside an authorized test environment.
  • Specific performance thresholds, load volumes, supported API versions, and detailed test data; these require stakeholder agreement.

6. Test Strategy

  1. Design: Derive scenarios and test cases from confirmed requirements and API documentation. Apply equivalence partitioning, boundary value analysis, decision tables, state transition testing, use-case testing, and error guessing.
  2. Prioritize: Prioritize cases by business and technical risk once impact and severity criteria are agreed.
  3. Smoke and sanity: Run smoke checks on a candidate build. If critical smoke checks fail, report the failure and request a stable build before in-depth execution.
  4. Execution: Run functional, validation, integration, authentication, regression, compatibility, and exploratory checks across confirmed supported environments.
  5. Quality attributes: Conduct performance, load, concurrency, and rate-limit checks only with approved limits, a suitable environment, and agreed thresholds.
  6. Defects and retesting: Log defects in JIRA, retest fixes, and repeat relevant regression coverage until agreed exit criteria are met.

Apply context-driven, shift-left, exploratory, and end-to-end testing practices. Multiple testers may execute across supported environments in parallel when access and test data permit.

10. Test Execution

  • Verify the target environment, build, credentials, permissions, and test data before starting.
  • Run and record smoke tests; communicate blockers before proceeding to detailed testing.
  • Execute prioritized cases and exploratory checks; capture actual results and evidence.
  • Log failures in JIRA, retest fixes, and run related regression checks.
  • Summarize progress, defects, blockers, and risks to stakeholders on the agreed cadence.

11. Test Closure

At the end of the test cycle, consolidate execution results, defect status, outstanding risks, coverage, and any deviations from the plan in a test summary report. Obtain stakeholder review and record the agreed closure or follow-up actions.
